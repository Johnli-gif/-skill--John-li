# A股热点风格工作台

一个用于日常中国 A 股热点分析的本地 Web 面板。当前版本聚焦三件事：

- 根据你的交易周期、风险承受、熟悉行业和仓位纪律，对候选赛道和可执行个股做优先级排序。
- 用“今日操作建议与作战页”优先完成数据确认，再给出唯一的当日买卖指令，包括当前持仓处理价、候选埋伏买入价、止损价和目标价；其他模块只做校验与参考。
- 跟踪“30 天收益目标”，把起始资产、当前资产、目标资产、防守底线和阶段仓位计划放在同一个面板里。
- 使用“仓位预算参考”把当前仓位、现金、8%回撤空间和单笔风险上限放在同一张校验表里，不再重复输出个股买卖建议。
- 每个交易日使用成交记录截图检查；当天有交易就在首屏和持仓截图一起上传券商“当日成交”截图，没上传则默认当天无交易，不阻塞一键刷新数据。
- 每天收盘录入账户资产，复盘是否偏离 30 天目标路径，并同步更新目标追踪进度。
- 在首屏一次性上传国元点金、同花顺等券商持仓截图，保存为最新持仓凭证，并通过浏览器本地 OCR 识别成持仓表；持仓体检、仓位推演和资讯模块都同步读取同一份数据。
- 识别后把每只股票的成本、现价、盈亏和行情快照放进持仓体检；持仓体检只做数据核对，具体买卖动作仍回到首屏今日操作建议。
- 展示“重大财经资讯预告”，按经济数据、科技突破、能源电网和外部风险筛选对 A 股影响较大的事项，并显示具体资讯内容、判断信号、利好板块、头部个股和利空注意事项。
- 一键刷新公开行情，更新持仓现价、市值、浮盈亏，同时读取上证、深成、创业板、科创50作为市场闸门；市场未允许进攻时，候选股即使到价也不会生成买入股数。

风格画像面板已从界面移除；内部仍保留默认偏好参数用于热点评分，避免历史评分逻辑突变。

## Today Orders 说明

- `GET /_today_orders?source=battle`：返回按持仓/候选汇总的今日执行建议（用于服务端同步结果）。
- `POST /_today_orders`：用于回填执行反馈，`body` 中的 `feedback` 会被合并后保存。

```text
POST /_today_orders
{
  "feedback": { "000001": { "code": "...", "status": "executed", "updatedAt": "..." } }
}
```

所有数据会保存在浏览器本地 `localStorage` 中；服务端仅辅助静态资源和接口落盘。点击侧栏的“重置本地数据”可以恢复样例数据。

## 开发说明（补丁发布前）

## 界面优先级

页面按决策紧急度排列：

1. `今日操作建议与作战页`：第一屏先导入今天最新持仓截图、OCR 识别生成持仓表、确认表格与截图一致并一键刷新行情；四项完成后才显示持仓卖出/减仓/持有建议，以及可提前埋伏标的的买入触发价、风控价和目标价。
   每条建议会同时显示“目标影响”：持仓卖出会显示预计释放资金和减少暴露，候选买入会显示投入资金、止损风险和买后仓位，持有会显示当前浮盈/浮亏对 30 天目标缺口的贡献或拖累。
   每条建议还可以回填执行结果：已执行、部分执行、未触发或主动放弃，并记录实际成交价、股数和备注。回填只用于复盘和校准，不会自动改持仓；真实持仓仍以你下一次上传的券商截图为准。
2. `30天目标`、`持仓体检`、`仓位预算`：只用于确认净值、仓位、持仓数据和风险预算，不再输出独立买卖建议。
3. `成交记录检查`：用于复盘当天是否按计划执行；未上传成交截图则默认当天无交易。
4. `收盘复盘`：只保留目标偏离和执行纪律复盘。
5. 低优先级的截图接入、观察池、交易复盘、独立买入清单已移除；截图统一在首屏上传，个股执行统一看顶部“今日操作建议”。

## 30 天目标追踪

“30 天收益目标追踪”用于把激进收益目标拆成可执行的阶段计划：

1. 录入起始资产、当前资产、现金余额、目标收益率、最大回撤和目标日期。
2. 面板自动计算目标资产、距离目标、完成进度、防守底线和盘中估算净值。
3. 盘中估算净值使用“现金余额 + 最新持仓市值”，用于判断实时目标偏离；正式目标资产仍以你手动保存的收盘复盘为准。
4. 目标路径固定按“交易日推进”计算：按周一至周五推进，不额外扣除法定节假日。
5. 目标路径会显示今日路径线、盘中估算偏离、5 日目标线、本周必须线和剩余日均收益。
6. 当盘中估算与手动资产偏离超过 `5000` 元、估算净值落后目标路径超过 `5000` 元、或接近 `8%` 防守线时，会出现预警条。
7. 阶段计划会把目标拆成第 1 阶段、第 2 阶段、第 3 阶段和目标线，对应仓位推进和风控动作。
8. 首屏“今日操作建议”会把目标缺口、市场闸门、持仓硬线和候选触发统一成唯一买卖入口；目标页只显示路径和风险校验。

这个面板只做交易纪律和进度管理，不保证收益。若账户跌破防守底线，应先停止进攻并复盘，而不是继续加仓摊低成本。

## 仓位预算参考

“仓位预算参考”用于在行情触发后先算清楚总仓位和风险余量，而不是临盘凭感觉追：

- 显示当前仓位、估算现金、单笔风险上限和距离 `8%` 防守线的空间。
- 分别计算 `35%` 防守验证、`45%` 第一阶段上限、`70%` 强确认进攻、`80%` 极高确定性四档对应还能新增多少资金。
- 不再显示具体候选股、可买股数或个股买卖动作，避免和首屏“今日操作建议”重复。
- 市场闸门、候选触发、个股股数、执行价、风控价统一集中在首屏“今日操作建议”。
- 仓位比例使用盘中估算净值作为分母，避免行情刷新后仓位仍按旧资产口径计算。

这个模块的作用是执行前校验。具体买入、卖出、减仓、观察动作只看首屏“今日操作建议”。

## 每个交易日成交记录检查

“交易日成交记录检查”把原来的逐项勾选改成截图证据流：

- 当天有交易：在首屏和持仓截图一起上传券商“当日成交”截图，面板保存截图凭证，并尝试识别买入/卖出、股票、成交价、成交量和成交额。
- 当天无交易：不用上传成交截图，面板默认当天无交易，不阻塞一键刷新数据，也不会因为没有逐项勾选盘中清单而扣纪律分。
- 原 `09:45` / `14:30` 规则仍作为自动检查逻辑显示，用于说明系统如何判断风险和执行，不再要求手动逐项填写。

清单会按日期自动重置。当前默认规则仍包括：通富微电跌破 `70.8` 减持一半仓位，账户目标最大回撤放宽到 `8%`，但这些规则只作为复盘解释和自动检查依据。

收盘复盘会优先读取当天成交截图和今日建议回填，并生成“执行纪律”评分。未上传成交截图会被视为无交易日；上传后即使 OCR 不稳定，也会保留截图作为有交易凭证，真实持仓仍以下一次持仓截图为准。关键买卖建议如果选择“主动放弃”，仍会进入纪律摘要。纪律分会随收盘复盘一起保存，便于区分“行情判断错”还是“计划没执行”。

## 今日操作建议与收盘复盘

“今日操作建议”统一承载两层信息：

- 赛道提前布局：回答未来 1-2 周哪些方向可能先启动、触发条件是什么、失效条件是什么、预期空间和主观概率是多少。
- 个股执行卡片：回答哪只股票、当前是否触发、什么价位可以买、什么价位禁追、止损在哪里、目标在哪里、预算多少。

今日操作建议只记录触发式机会，不表示无条件买入。当前默认候选池不再局限于当前持仓，分为两类：

- 持仓联动/替代：帝尔激光、蓝思科技、华天科技等，用于处理当前科技仓附近的机会。
- 全局赛道：中际旭创、北方华创、埃斯顿、恒瑞医药、国电南瑞等，用于观察 AI 光模块、半导体设备、机器人、创新药、电网设备等外部轮动机会。

系统会按赛道评分、主观概率、是否触发买点、是否与现有持仓冲突、交易复盘反馈、买后仓位和单笔风险排序。没有触发条件时只显示“等待”，不会生成买入股数。

仍有数量或市值的当前持仓会参与候选池降权：例如通富微电会让先进封装/封测替代仓降低优先级，沪电股份和英维克会影响 AI 算力链仓位叠加，帝尔激光会影响玻璃基板方向的新增仓位。系统会过滤“科技、设备、材料”等过宽标签，避免把不相关赛道误判为重叠。这样候选池可以全局看机会，但不会无意识把仓位集中到同一条赛道。

交易复盘会参与候选池校准：盈利反馈会给同股或同赛道候选加分，亏损反馈会降权；样例记录不会参与评分。这样后续建议会逐步贴近你的实际执行结果，而不是只依赖初始主观概率。

“收盘目标偏离复盘”用于每天收盘后录入账户资产。保存后会同步更新 30 天目标追踪，并用“收盘资产 - 当前持仓市值”推导新的现金余额，作为下一次行情刷新时的估算基础。同时会保存当天执行纪律分、关键漏项和复盘备注。

## 券商截图数据

本工具不会创建仿国元点金、同花顺或任何券商的登录框，不保存账号密码，也不会后台读取你的真实券商账户或绕过软件权限读取持仓。正确流程是：

1. 你在国元点金、同花顺或其他券商软件里自己打开持仓页。
2. 截取当前持仓页。
3. 在最上端“今日操作建议与作战页”上传持仓截图；如果当天有成交，再一起上传“当日成交”截图。
4. 点击“一键刷新数据”，工作台会同步处理持仓 OCR、成交 OCR 和公开行情；如果没有上传成交截图，则默认当天无成交记录。

截图导入会把图片保存为最新持仓凭证。首屏提供“识别截图生成持仓表”，在浏览器本地尝试 OCR；识别成功后仍需要你核对股票、代码、股数、成本和现价。若 OCR 有误，可以直接在首屏持仓表里修正；若 OCR 漏掉某只持仓，可以在同一张校准表里“新增一行”手动补齐，也可以删除误识别行。补齐后再点击“确认表格与截图一致”，才会允许生成今日操作建议。

独立的“券商截图接入中心”已删除，所有截图入口统一放在首屏。面板不是登录入口，也不会要求输入国元点金、同花顺或任何券商密码。

## 面板上传与对话框上传的区别

- 在 HTML 面板上传截图：触发本地浏览器 OCR、结构化持仓/成交记录、公开行情刷新、内置规则引擎和执行面板更新。它适合你盘中快速看“今天怎么做”。
- 在 Codex 对话框上传截图：触发 `caijing-redian-fenxi` skill 的完整分析流程，我可以结合你的最新截图、实时公开信息、板块新闻和你的历史偏好给出更完整的主观判断。
- 因此两者不是完全等价。面板上传不会自动调用 Codex skill，也不会自动联网抓取全网资讯；对话框分析更完整，面板更快、更适合执行。
- 推荐日常流程：把持仓截图和当日成交截图发到 Codex 对话框，由我读取并结合实时公开信息做完整判断；我再把结构化持仓、成交记录和操盘建议同步到面板。你主要通过面板查看当日买卖价位、仓位预算、候选清单和复盘信息。

## 重大财经资讯预告

首屏会显示“重大财经资讯预告”，用于跟踪可能影响 A 股风险偏好和核心板块的事项：

- 经济数据：PMI、CPI/PPI、社融信贷、LPR、美国 CPI/非农/FOMC 等。
- 科技突破：AI 算力、光模块、液冷、先进封装、玻璃基板、国产半导体设备等。
- 能源电网：迎峰度夏、电网投资、特高压、储能并网、能源价格波动等。
- 外部风险：出口管制、地缘冲突、汇率波动和海外高估值成长股回撤。

未完成首屏截图导入、持仓确认和行情刷新前，该模块只显示通用影响方向、具体关注事项和判断信号；完成数据确认后，会额外标注与你当前持仓和候选股有关的联动事项。

## 结构化持仓

“载入样例持仓”仅作为备用测试入口。日常决策以当天最新截图 OCR 识别出的持仓表为准：

- 通富微电、沪电股份、英维克、帝尔激光。
- 已清仓的思源电气、汇川技术不计入有效持仓。
- 每只股票包含当前计划、止损/减仓线和加仓/止盈触发条件。

如果盘中成交发生变化，优先回到首屏重新上传最新持仓截图并重新 OCR。OCR 表格允许人工校正、补录漏识别行和删除误识别行，但这个结构化持仓只是为了辅助复盘和执行纪律，仍以你券商账户实际数据为准。

## 公开行情刷新

“刷新行情”会调用公开行情源，覆盖持仓、候选买入清单中的股票代码，以及上证、深成、创业板、科创50四个关键指数。刷新成功后：

- 持仓现价、市值和浮动盈亏会按最新价重算。
- 通富微电、沪电股份、英维克、帝尔激光会根据硬触发线显示“减半线触发”“保护线触发”“可留不加”“加仓触发区”等状态。
- 全局候选清单会显示是否进入触发区、失效区或禁止追高区；新增赛道候选使用相对涨跌幅、禁追幅度和动态止损做初筛。
- 今日操作建议会显示“市场闸门”。当上证/深成和创业板/科创50同步走弱时，新仓暂停；当指数多数转强且科技线配合时，才允许候选股按预算生成可买股数。

行情刷新只用于本地辅助判断，不连接券商账户，不自动下单，也不会改动“30 天目标追踪”里的账户资产。账户资产仍建议每天收盘后手动录入。

## 当前边界

当前热点板块、赛道逻辑和候选股概率仍是内置样例，不是实时新闻模型。持仓和候选股现价可以通过“刷新行情”读取公开行情源，但板块热度、新闻催化和资金流仍需要后续继续接入。

赛道和个股模块是观察候选，不是确定性买点。预计上涨区间和概率来自内置评分规则和主观情景假设，不是实时行情模型。本工具只做决策辅助，不构成具体买卖建议。

## 云端盯盘提醒

`scripts/cloud_monitor.py` 是给云服务器使用的独立盯盘脚本。它不会登录券商账户，也不会自动下单；它读取 `data/panel-sync.json` 中由对话框/面板同步过来的最新持仓和交易事实，再拉取腾讯公开行情，按 `config/cloud-monitor-rules.json` 里的风控线、观察线和候选股触发价生成提醒。

支持的提醒通道：

- 微信：企业微信机器人 `WECHAT_WORK_WEBHOOK_URL`、PushPlus `PUSHPLUS_TOKEN`、Server酱 `SERVERCHAN_SENDKEY`。
- 邮件：SMTP，支持 QQ 邮箱、企业邮箱等。
- 短信：通用 `SMS_WEBHOOK_URL` 或阿里云短信。阿里云短信需要先审核签名和模板。

本地测试：

```bash
cd /Users/johnlimacbook/Documents/财经热点
python3 scripts/cloud_monitor.py --dry-run --force --ignore-trading-time
```

### 免费无服务器方案：GitHub Actions

如果没有云服务器，优先使用 GitHub Actions。项目已内置 `.github/workflows/ashare-monitor.yml`，推送到 GitHub 后会在 A 股交易时段按北京时间每 10 分钟运行一次。

官方边界：

- GitHub Actions 定时任务使用 cron，默认按 UTC 时间运行，最短间隔为 5 分钟；本项目已把北京时间交易时段折算成 UTC。
- 公共仓库使用标准 GitHub-hosted runner 免费；私有仓库有免费分钟额度，超出后才会计费。
- 通知密钥通过 GitHub Actions repository secrets 保存，不写入代码库。

上线步骤：

```bash
cd /Users/johnlimacbook/Documents/财经热点
git init
git add .
git commit -m "Add A-share monitor"
git branch -M main
git remote add origin git@github.com:你的GitHub用户名/ashare-monitor.git
git push -u origin main
```

然后在 GitHub 仓库中设置提醒密钥：

```text
Settings -> Secrets and variables -> Actions -> New repository secret
```

推荐先用 PushPlus，最简单：

```text
PUSHPLUS_TOKEN=你的PushPlus token
```

也可以改用企业微信机器人：

```text
WECHAT_WORK_WEBHOOK_URL=企业微信群机器人 webhook
```

或邮件：

```text
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USERNAME=你的邮箱
SMTP_PASSWORD=邮箱授权码
MAIL_FROM=你的邮箱
MAIL_TO=接收邮箱
```

手动测试：

```text
GitHub 仓库 -> Actions -> A-share monitor -> Run workflow
dry_run=true 只打印不发送
force=true 强制忽略重复提醒限制
```

日常更新持仓：

1. 在本对话上传最新持仓/成交截图。
2. 我把结构化数据同步到 `data/panel-sync.json` 和必要的规则文件。
3. 你把改动推送到 GitHub。
4. GitHub Actions 自动按最新持仓继续盯盘。

云服务器部署示例：

```bash
sudo mkdir -p /opt/ashare-monitor
sudo rsync -av --delete ./ /opt/ashare-monitor/
sudo cp /opt/ashare-monitor/config/cloud-monitor.env.example /etc/ashare-monitor.env
sudo nano /etc/ashare-monitor.env
sudo cp /opt/ashare-monitor/deploy/ashare-monitor.service /etc/systemd/system/
sudo cp /opt/ashare-monitor/deploy/ashare-monitor.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ashare-monitor.timer
systemctl list-timers | grep ashare-monitor
```

备用 cron 方案：

```bash
sudo crontab -e
# 粘贴 deploy/ashare-monitor.cron 中的一行
```

默认规则：

- 每 10 分钟运行一次。
- 仅在 A 股交易时间内真正检查，非交易时间自动跳过。
- 默认 `ALERT_MIN_LEVEL=actionable`，只推送买入/卖出等可执行触发；观察线不会打扰。
- 同一批触发条件 30 分钟内不重复提醒，可用 `QUIET_REPEAT_MINUTES` 调整。

持仓更新流程：

1. 在 Codex 对话框上传最新持仓/成交截图。
2. 我把结构化结果写入 `data/panel-sync.json`。
3. 将最新项目目录同步到云服务器，例如 `rsync -av --delete ./ root@服务器IP:/opt/ashare-monitor/`。
4. 云端定时器继续按最新持仓规则监控。
